# 后台重构验收范围

目标包括：接口清单；反馈状态保存并刷新后仍保留；公开回复与内部备注权限；去掉大块回复空白；普通输入不重建表单；取消公开反馈 CF 验证及标题、描述最短/最长字符限制；项目、分类、图片上传与外链缓存；关于资料全部分组编辑；密码及退出；手机和桌面单主内容区、整页滚动；源码推送与线上资源核对；收到新反馈后企业微信 text 通知及发送回执验证。

参考：[Webby 网站评审标准](https://www.webbyawards.com/judging-criteria/)、[iF 评审标准](https://ifdesign.com/en/if-design-award-and-jury)。

设计检查采用此前指定的 Webby（内容清楚、导航直观、功能有效）及 iF（形式服务功能、操作一致、可维护）原则。评审不等于获奖或赛事认证；按真实任务检查，不追求装饰与无法证明的“再无可优化之处”。

核心验收：
- 收件箱：筛选、搜索、分页、详情、四种状态持久化、公开回复、内部备注、错误不吞掉输入。
- 项目：新增、编辑、三个展示标记、分类、排序；图片上传、处理、站内返回、替换及旧对象清理。
- 分类：添加、保存、空分类删除、非空分类保护。
- 关于：五个分组、链接/复制/二维码、增加删除排序、版本冲突保护。
- 安全：任意非空密码、鉴权、跨站写入保护、限流、附件私密访问、内部备注不外泄。
- 性能与布局：输入不发保存请求、不重渲染全页；只局部更新数据；桌面与 390/320 手机宽度无横向溢出和嵌套滚动。
- 推送：仅配置在服务端，文本摘要不超企业微信字节限制；提交成功不依赖推送成功；实际发送回执。

发布前保留线上正式数据，不将开发演示数据覆盖线上。清理旧 React/Ant Design 后台、旧 CSS 和构建残留。实际验证结果在完成后补充，不用构建成功冒充实际功能验证。
